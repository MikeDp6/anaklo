# ADR-0003: Διαθεσιμότητα και κράτηση σε SQL

- Κατάσταση: αποδεκτό
- Ημερομηνία: 2026-09-27

## Πλαίσιο
Το SPEC v0.3 έλεγε «Edge Function ή SQL» για τη διαθεσιμότητα και ζητούσε tests σε Vitest. Αν τα slots υπολογίζονται σε μία γλώσσα και ο έλεγχος της κράτησης σε άλλη, οι δύο εκδοχές θα αποκλίνουν. Υπάρχει και το ζήτημα των Edge Functions: αυξάνουν τον χρόνο απόκρισης (cold start) και δεν μπορούν να κάνουν έλεγχο και κράτηση στο ίδιο transaction.

## Απόφαση
Η διαθεσιμότητα και η κράτηση υλοποιούνται **σε Postgres (plpgsql/SQL)**, με το μοτίβο wrapper του ADR-0005. Η λογική βρίσκεται στο `private.*_impl` (SECURITY DEFINER, `search_path = ''`), και το API βλέπει λεπτά SECURITY INVOKER wrappers στο `public`.
- `available_slots(...)`: STABLE. Καλείται από τη σελίδα κράτησης μέσω RPC, με συγκεκριμένα πεδία εξόδου. Το `anon` δεν μπορεί να ελέγξει συμμετοχή σε επιχείρηση, οπότε το impl ελέγχει κάτι άλλο:
  - ότι η επιχείρηση έχει `booking_enabled`
  - ότι αγνοούνται οι ανενεργοί επαγγελματίες και οι ανενεργές υπηρεσίες
- `book_appointment(...)`: η λογική σε SECURITY DEFINER impl. Το wrapper εκτελείται μόνο από `service_role` (Edge Function OTP) και, σε λειτουργία προσωπικού, από `authenticated` με έλεγχο ρόλου.
  - Κλείνει advisory lock ανά επιχείρηση + τοπική ημέρα.
  - Καλεί την ίδια λογική για να ξαναελέγξει ότι η ώρα είναι διαθέσιμη.
  - Υπολογίζει διάρκεια και τιμή στον server.
  - Σέβεται το idempotency key.
  - Κάνει το insert.
  - Αν χτυπήσει το exclusion constraint (`23P01`), το μετατρέπει σε «η ώρα μόλις κλείστηκε».
- Η δημόσια κράτηση περνά πρώτα από την Edge Function OTP/έμπιστης συσκευής (ADR-0006), που μετά καλεί το `book_appointment`. Το `anon` **δεν** έχει `EXECUTE` στο `book_appointment`.
- Όλη η λογική ώρας γίνεται με `AT TIME ZONE businesses.timezone`:
  - κάθε τοπικό διάστημα μετατρέπεται μία φορά ανά ημερομηνία
  - τα slots μπαίνουν σε τοπικό πλέγμα
  - τα διαστήματα δεν περνούν τα μεσάνυχτα

## Συνέπειες
- Τα tests της διαθεσιμότητας γράφονται σε **pgTAP** (`supabase test db`) και τρέχουν τοπικά με Docker και στο CI:
  - αλλαγή ώρας (29/3 και 25/10/2026)
  - τοπικές ώρες 00:00–02:59
  - εξαιρέσεις ωραρίου, μισή μέρα
  - δεύτερη ζώνη ώρας
- Το Vitest δεν τεστάρει διαθεσιμότητα.
- Δεν επιτρέπεται δεύτερη υλοποίηση (π.χ. σε TypeScript). Το UI απλώς δείχνει ό,τι επιστρέφει η RPC.
