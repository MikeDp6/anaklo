## 0. Decisions (defaults binding for the builders; ⚠ = beyond or against the plan text, repeated in §7 for Michalis)

**Database**
1. **Family.** A client's family = its root + every client whose `merged_into_id` chain reaches the root. Every read and write of 1.8 is family-wide (`private.client_family`). `merge_clients` **flattens** (the source's own sources are re-pointed to the target), so families stay one level deep; the helpers still recurse (≤ 32 levels) as defence against rows written by `service_role`.
2. **Merge** (owner/manager, not critical, no fresh code): moves `appointments`, `client_notes` and `messages_log.client_id` from source to target; **consents stay on the source** (plan) and are read through the family; fills the target's **empty** `phone_e164` (with its `phone_verified_at`), `email`, `birthday` from the source, never `full_name`/`locale`; idempotent (`merged: false`); a merged or erased participant → **AN033**; cross-business → `42501`. **No merge UI in Phase 1** (plan «Αναβάλλονται», D7: Phase 3 with the importer): the exit criterion «Owner και manager καλούν το `merge_clients` μέσω του wrapper» is met by pgTAP calling `public.merge_clients` as `authenticated` owner and manager, and by one e2e PostgREST call (§5.4).
3. **`merge_clients_core(p_business_id, p_source, p_target, p_actor)`**, no grants, `p_actor ∈ ('staff','import')`: `staff` needs `auth.uid()` and declares nothing; `import` declares `anaklo.actor_type = 'import'` inside the core (plan «Κανόνες»). The merge fires no appointment trigger (only `client_id` changes), the actor is for the audit row: **`audit_log.actor_type` gains `'import'`** (CHECK + `AUDIT_ACTOR_TYPES`).
4. ⚠ **Erase is refused while the family has an appointment `booked|confirmed` with `ends_at > now()`** (in progress included) → **AN032**. The owner cancels it first through the existing flows (with or without SMS: once erased nobody can reach the client about it). Past appointments stay, anonymous (plan).
5. ⚠ **Erase acts on the whole family**, also when called with a merged source's id (the merge said they are one person).
6. **Erase list (§2.7) goes beyond the plan's in three places**, all links derived from the person: `clients.external_ref`, `appointments.request_hash` (sha256 of a payload that contains the name and phone, 0004) and `appointments.external_ref` are nulled. `otp_challenges.phone_hmac` becomes **nullable** so it can be wiped (plan «τηλέφωνα των otp_challenges»). `trusted_devices` keep their HMAC (revoked; the 1.5 purge drops them 30 days later). `messages_log.provider_message_id` is kept (late delivery reports still find their row; provider-side deletion is a DPA item, §6).
7. ⚠ **Suppression for every phone of the family, also when another live client of the business shares it** (plan-literal; families share mobiles, SPEC §7): that client's marketing and **import**-appointment reminders to the number stop (1.5 rule 7(c)); transactional SMS (confirmations, reminders of non-import bookings, cancellations) continue. Alternative in §7.
8. **Consents: `authenticated` writes only through `set_client_consent`** (definer). Direct `INSERT`/`UPDATE` on `client_consents` are revoked and the policies `client_consents_insert`/`client_consents_withdraw` dropped (no app code uses them; the family rule would otherwise live in TypeScript, rule 13). **State rule in one SQL helper** (`private.consent_state`): per purpose, the latest (`created_at desc, id desc`) **active** (`withdrawn_at is null`) record of the family wins → `granted` / `refused`; none → `none`. This is the 1.3 rule, made family-wide. Toggle **on** = a **new** record (`legal_basis 'consent'`, `source 'staff_ui'`, `granted true`) only when the state is not `granted`; **off** = `withdrawn_at` on **every** active `granted` record of the family for that purpose (usually one); staff never write a refusal record; never a change of `purpose`/`granted` (the guard enforces it anyway). `legal_basis` per purpose: `staff_ui` → always `consent` (the 0002 CHECKs allow `soft_opt_in` only from `booking_form`, only for marketing). The PWA offers only `marketing_sms` in Phase 1; the RPC accepts the four purposes.
9. ⚠ **The 1.3 booking box becomes family-aware**: 0010 redefines `book_appointment_impl` with step 5 moved into `private.apply_marketing_box` (the same rows as today, compared against the **family** state). Without it, after a merge a «checked» box on the root (1.3 reads only the root's own records) could leave in force a source's grant that is newer than the root's latest record. The box still never withdraws (a refusal record wins by recency; «Το ίδιο ισχύει για το κουτί» = new records only, never a rewrite). `10_public_booking` must stay green unchanged.
10. **Notes stay direct table writes** (the 0002 policies: any member adds with `author_id = auth.uid()`, the author or the owner deletes), plus `INSERT (id)` for client-generated ids (retry = upsert ignore-duplicates, as 1.6). No edit in the UI (delete + add). One guard trigger function on `client_notes` and `client_consents` (**every role**, `service_role` and the booking included): no note or consent for an **erased or merged** client → **AN033**; it reads the client `FOR KEY SHARE`, so it waits for a merge/erase in flight and then sees its result.
11. **Details edit** (name, phone, message language) by **every role**, direct `UPDATE` through the existing 0002 column grants; the CHECK already refuses identifying values on an erased row.
12. **New domain errors:** AN032 `client_has_upcoming` (409), AN033 `client_unavailable` (409).
13. **`client_card`**: one RPC, any member, `p_now` on the `_impl` only. History = the next **10** upcoming + the latest **50** past + totals; notes = latest **100** + total. No server paging in Phase 1.
14. ⚠ **Staff see the whole history of a client** (date, service, staff, status), colleagues' appointments included (SPEC §5: staff see every client and the notes); **amounts only for their own appointments**, nulled inside the `_impl`. Owner/manager: every amount. No money total on the card (LTV is Phase 2 memory).
15. **Ring (E18)** = days since the last visit (business-local dates) against the interval of `next_visit_hint_impl` in days (**weeks × 7**: exactly the interval the client is told after booking, 1.3). States `no_visits`, `no_interval`, `within`, `beyond`; computed in SQL, the browser only draws it. The personal interval is Phase 2 memory.
16. **Card of an erased client** = the state only (no anonymous history). **Merged source** = the state + its root id; the PWA redirects.
17. **`search_text` of an erased client is exactly `''`** (`set_client_search_text` redefined).

**PWA**
18. **«Πελάτες» = a fourth tab for every role**; routes `clients` and `clients/:clientId`; a «Καρτέλα πελάτη» link in the appointment sheet (the barber reads the notes before the cut).
19. **Erase confirmation** = the consequences + a checkbox «Καταλαβαίνω ότι δεν αναιρείται.» (no typing of the name); then `useStepUp`; success only after the answer → back to the search with a notice.
20. **Primary action of the card** = «Κλήση» (the ring's action: SPEC «κάθε μετρική με κουμπί ενέργειας»); without a phone «Επεξεργασία στοιχείων».
21. **1.4 fix**: `fetchStaffDay` maps an erased client to `client: null` (today it would print `''` instead of «Walk-in χωρίς όνομα»).
22. **E2E**: the erase scenario runs on its own provisioned shop with `signInAal2` (the same API-made `aal2` session as the setup), not on the shared setup owner the plan names: 1.7 §7.4 forbids critical actions on that shared session.
23. **Estimate:** the consent RPC and box helper, the edit sheet, the appointment link and the calendar fix add ≈ 0.5 day to the 2.5 of 1.8 (from the buffer).

### 2.1 Order and conventions

Header comment (what, contract link, the family rule, «erase = anonymisation, never cascade») → `raise_domain_error` (full list to AN033) → schema (§2.2) → helpers and triggers (§2.3) → `book_appointment_impl` (§2.4) → RPCs (§2.5) → grants (§2.9). Same conventions as 0006–0009: `set search_path = ''`, qualified names, **never `strict`**, `_impl` = `private` SECURITY DEFINER, wrapper = `public` `language sql` SECURITY INVOKER with the same parameters (minus `p_now`) and volatility. CHECKs on value lists written `constraint <table>_<column> check (<column> in (…))`.

Check order in every `authenticated` `_impl`: (1) `private.is_member(p_business_id)` else `42501`; (2) role else `42501` (merge: owner/manager; erase: owner); (3) erase only: `perform private.require_fresh_totp()`; (4) client ids: null, or no row `(p_business_id, id)` → `42501`; argument shape → `22023`; (5) writers: `pg_advisory_xact_lock(hashtextextended('clients:' || p_business_id, 0))`, then the rows they change re-read `FOR UPDATE` (order by `id`); (6) the operation. **No actor is declared** by any `authenticated` RPC; only `merge_clients_core` with `p_actor 'import'` declares `import`.

### 2.5 RPCs for `authenticated` (wrapper + `_impl` granted)

| Wrapper (parameters in this order) | `_impl` | Returns | Vol. | Role | Fresh code |
|---|---|---|---|---|---|

**`client_card_impl`**: (1) membership; `p_now` null → `22023`; (4) the client. Erased (`erased_at` not null, also for a source) → `{ state: 'erased', client_id, erased_at }`. Merged → `{ state: 'merged', client_id, merged_into_id: client_root(…) }`. Live → §2.6 over `client_family(b, client_id)`. Role values from `has_role`/`my_staff_id` (D2-aware); never the JWT.

**`set_client_consent_impl`**: (1) membership; (4) client; shape (`22023`): `p_purpose` ∉ `CONSENT_PURPOSES`; `p_granted` null; when `p_granted`: `p_given_by` ∉ `('client','guardian')`, or `p_policy_version` null or not 1–40 characters (`p_given_by`/`p_policy_version` ignored when not granted). (5) lock; the client re-read `for update`: erased or merged → **AN033**. (6) `before := consent_state(b, c, p_purpose)`. Granted: `before.state = 'granted'` → nothing; else insert `(b, c, p_purpose, 'consent', true, 'staff_ui', p_policy_version, p_given_by, created_by auth.uid())` (`created_at` default). Not granted: `update client_consents set withdrawn_at = now() where client_id in family and purpose = p_purpose and granted and withdrawn_at is null` (the guard stamps `now()`). Returns `{ client_id, purpose, state: <consent_state after>, changed: boolean, consent_id: uuid|null, withdrawn: int }`. No audit row (the records are the evidence).

**`merge_clients_impl`**: (1) membership; (2) `has_role(p_business_id, array['owner','manager'])`; then `return private.merge_clients_core(p_business_id, p_source, p_target, 'staff')`.

**`merge_clients_core`** (callers check membership; no grants):
1. `p_actor` ∉ `('staff','import')` → `22023`; `staff` and `auth.uid()` null → `42501`; `import` → `set_config('anaklo.actor_type', 'import', true)`.
2. `p_source` or `p_target` null → `42501`; equal → `22023`.
3. Lock; both rows of the business `for update` (order by id); fewer than two → `42501` (cross-business, unknown).
4. Source `merged_into_id = p_target` → `{ source_id, target_id, merged: false, appointments: 0, notes: 0, messages: 0, repointed: 0, filled: [] }`, nothing written.
5. Source or target erased, source merged elsewhere, or target merged → **AN033**.
6. `update appointments set client_id = target where business_id = b and client_id = source` (no trigger fires: `client_id` is in neither trigger's column list); same for `client_notes.client_id`; `messages_log.client_id` (+ `updated_at`; queued SMS then go to the target's phone at claim, 1.5 D24).
7. Flatten: `update clients set merged_into_id = target where business_id = b and merged_into_id = source`.
8. Fill gaps of the target in one `UPDATE … FROM` the source: `phone_e164 = coalesce(t.phone_e164, s.phone_e164)`, `phone_verified_at = case when t.phone_e164 is null then s.phone_verified_at else t.phone_verified_at end` (same statement, so the 0002 trigger keeps it), `email = coalesce(…)`, `birthday = coalesce(…)`. `filled` = the subset of `phone`,`email`,`birthday` (this order) that changed.
9. `update clients set merged_into_id = target where id = source`. Consents untouched. `otp_challenges`, `trusted_devices` (phone-bound), `booking_tokens` (appointment-bound), push rows (no `client_id`), `suppression_list`: untouched.
10. Audit `clients_merged`. Returns `{ source_id, target_id, merged: true, appointments, notes, messages, repointed, filled: text[] }`.

A booking racing a merge (its FK check waits on the `FOR UPDATE`) may still land on the source after the merge; every 1.8 read is family-wide, so nothing is lost.

**`erase_client_impl`**:
1. Membership; owner; **`perform private.require_fresh_totp()`** (C6: `42501` hint `aal2_required` | `fresh_totp_required`, nothing written); client (`42501`).
2. Lock; `root := client_root(b, p_client_id)` (after the lock); the family rows `for update` (order by id).
3. Root already erased → `{ client_id: root, erased: false, erased_at: <original>, erased_ids: [], appointments_kept: 0, notes_deleted: 0, consents_deleted: 0, messages_wiped: 0, otp_challenges_wiped: 0, devices_revoked: 0, tokens_revoked: 0, suppressed: 0 }`, nothing written, no audit.
4. A family appointment `status in ('booked','confirmed') and ends_at > now()` → **AN032**, nothing written.
5. `phones := distinct non-null phone_e164 of the family`; `hmacs := private.phone_hmac(p)` for each (only when there is a phone: a phone-less client needs no Vault key).
6. The writes of §2.7, then audit `client_erased`.
7. Returns `{ client_id: root, erased: true, erased_at, erased_ids: uuid[] (sorted), appointments_kept, notes_deleted, consents_deleted, messages_wiped, otp_challenges_wiped, devices_revoked, tokens_revoked, suppressed }` (`suppressed` = rows inserted).

- Every list and counter covers the family's appointments (`client_id ∈ family`).
- `visits` = distinct business-local dates (`starts_at at time zone tz`) with ≥ 1 `completed` appointment (SPEC §4 «Επίσκεψη»); `last_visit_at` = max `starts_at` of `completed`; `last_visit_date` its local date; `no_shows` = count of `no_show`. No phase, tag or money total (memory, Phase 2).
- `amount_cents`: raw = `completed` → `coalesce(charged_cents, total_cents)`, `booked|confirmed` → `total_cents`, else null; **kept only when** `has_role(owner, manager)` **or** `staff_id = my_staff_id(b)`, else null. `own` = `my_staff_id(b)` not null and equal to `staff_id`.
- `author_name` = the author's staff `display_name` through their membership of this business; `author_role` = that membership's role (null when no longer a member or the account is gone); `by_me` = `author_id = auth.uid()`; `can_delete` = `by_me` or `has_role(owner)` (the 0002 delete policy).
- `can.erase` = `has_role(b, owner)`; `can.merge` = `has_role(b, owner|manager)`. No freshness here (never proactive, 1.7 D18).
- **Ring**: `today := (p_now at time zone tz)::date`; `hint := private.next_visit_hint_impl(b, p_now)`; `interval_weeks := hint->>'weeks'`, `interval_days := weeks × 7`, `hint_key := hint->>'key'` (all null when `hint` is null).
  - no `completed` visit → `no_visits`, `days_since_last` null, `fraction 0`, `overdue_days` null (interval fields as computed);
  - else `days := greatest(0, today − last_visit_date)`; `hint` null → `no_interval`, `fraction` null;
  - `days ≤ interval_days` → `within`, `fraction = round(days::numeric / interval_days, 2)`, `overdue_days` null;
  - `days > interval_days` → `beyond`, `fraction = 1`, `overdue_days = days − interval_days`.
