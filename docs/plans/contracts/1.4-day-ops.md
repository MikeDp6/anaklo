## 0. Decisions in one place

1. **Idempotency.** `set_appointment_status` and `cancel_appointment` are idempotent by target state: when the appointment already has the requested status the call succeeds with `changed: false` and writes nothing. They take a required `p_from_status` (the status the UI showed); a different current status → **AN021** `appointment_changed` (no stale overwrite after another device changed it). Only `staff_move_appointment` stores an idempotency key (`private.move_requests`), because re-applying a move could undo a newer move. `staff_book_appointment` (0004) keeps its own key.
2. **Who may act.** Owner/manager: every appointment of the business. Any other member: only appointments with `staff_id = private.my_staff_id(p_business_id)` (a staff member with no staff row acts on nothing). Not allowed → `42501`. Staff may reassign **their own** appointment to a colleague (it is their own appointment that moves); never touch a colleague's.
3. **Status targets.** `set_appointment_status` sets only `confirmed | completed | no_show`; everything that ends in `cancelled` (normal cancel and correction into cancelled) goes through `cancel_appointment`. Leaving `cancelled` clears `cancelled_by`/`cancel_reason`; leaving `completed` clears `charged_cents` (the 0003 CHECKs require both).
4. **`cancelled_by`** = `'client'` when `p_reason = 'client_request'` (the client phoned), else `'business'`. The event actor stays `staff`.
5. **Time rules checked in the `_impl`, with domain errors, using `now()`** (the 0003 guard trigger reads `now()` too and stays the backstop): `completed`/`no_show` only when `starts_at <= now()` (**AN023** `not_started`); a staff correction among `completed/no_show/cancelled` only while `now() <= ends_at + correction_window_days` (**AN022** `correction_closed`). Owner/manager: no window.
6. **`p_notify` stores nothing persistent.** It is validated (not null), part of the move request hash, and handed to the planner as the transaction-local setting `anaklo.notify_client` (`'true'|'false'`). It is **effective** only for an appointment that starts in the future. Responses echo `notify` (effective) and `sms_queued` (this call queued an SMS). Until 1.5 the planner queues nothing for staff actions, so `sms_queued` is always `false`.
7. **Planner body v1.1 in 0006** (`create or replace`, signature unchanged): v1 plus the accepted value `p_change = 'status_changed'` (no effect yet). ⚠ The plan names only 0005 and 0007 as body changers; this is the one deviation, needed because v1 raises `22023` for any new `p_change` and the plan requires all three RPCs to call the planner.
8. **`busy_calendar` = the complement of RLS, plus working windows.** Blocks: only appointments the caller cannot read directly (owner/manager → none; others → every appointment not of their own staff row), without client, price or status. It also returns every active staff member's working windows of the day, because only SQL may compute them (exceptions, time off; rule 13) and staff cannot read colleagues' `time_off`. Returned as one jsonb (one round trip for the day frame).
9. **`today_summary`**: owner/manager = the whole business, others = their own staff row. `expected_revenue_cents` is JSON `null` for anyone who is not owner/manager, decided inside the `_impl`. ⚠ The plan's UI line says «μόνο για owner»; SPEC §5 gives the manager every amount, so the manager sees it too.
10. **`search_clients`**: substring match of the normalised query **and its greeklish variants** on `search_text` (gin trigram index), digits-only queries match phone digits; a fuzzy `word_similarity` pass only when the exact pass finds nothing. Deterministic ordering (§2.6.7).
11. **`private.job_runs` is append-only, one row per run**, failures included (the job catches its own error, records it, returns `null`). `private.record_job_run(...)` is the single writer.
12. **`auto_complete_impl`**: at most 1000 rows per run, `for update skip locked`, planner per row, one job run per call; pg_cron job `auto-complete` every 10′.
13. **Staff RPCs are `authenticated` only** (as 0004): nothing new for `service_role` or `anon`.
14. **`p_now` only on `today_summary_impl` and `auto_complete_impl`.** The mutations use `now()` like the guard trigger they rely on.
15. **Unknown outcome locks the form** (UI): after an offline/timeout failure a sheet accepts only «Δοκίμασε ξανά» (same payload, same key) or «Κλείσιμο» (closes and refetches the day). Changing anything is a new attempt with a new key, so a lost-but-committed attempt can never be doubled by an edited one.

```

  where status in ('booked', 'confirmed');                       -- auto-complete scan

private.job_runs                 -- heartbeats of every cron job (1.9 health reads them)

  job           text not null, constraint job_runs_job check (job in ('auto_complete'))  -- 1.5/1.9 extend the list

  rows_affected integer check (rows_affected >= 0)

  check (ok = (error is null))
```

#### 2.6.1 Common rules

- **Check order:** (1) `private.is_member(p_business_id)` else `42501` — before looking at any other argument; (2) every entity id belongs to `p_business_id` (`p_appointment_id` null or of another business → `42501`); (3) the operation's own rules. Declares **no actor** (→ `staff` with `auth.uid()`).
- Mutations lock the appointment `for no key update` (never `for update`; 1.3 §10 lock order: appointment row → day locks).
- Roles: `v_manager := private.has_role(p_business_id, array['owner','manager'])`; `v_own := appointment.staff_id = private.my_staff_id(p_business_id)`; mutations require `v_manager or v_own`, else `42501`.
- Invalid arguments the UI schemas already exclude (unknown status/reason, null key/flag/time) → `22023`.

| | owner / manager | staff (own staff row S) |
|---|---|---|
| `busy_calendar.blocks` | `[]` (reads all via RLS) | every non-cancelled appointment with `staff_id ≠ S` |
| `busy_calendar.windows` | all active staff | all active staff |
| `today_summary` scope / revenue | business / amount | S only / `null` |
| status, cancel, move | any appointment | only `staff_id = S` (move may set another staff) |
| corrections | any time | within `correction_window_days` after `ends_at` |
| `search_clients` | all live clients | all live clients |

#### 2.6.2 `busy_calendar` (stable)

1–2 as above; `p_local_date` null → `22023`. `tz = businesses.timezone`; `day_start = p_local_date::timestamp at time zone tz`, `day_end = (p_local_date + 1)::timestamp at time zone tz` (23 h or 25 h on DST days).

```
{ local_date: 'YYYY-MM-DD', timezone, day_start, day_end,
  windows: [{ staff_id, starts_at, ends_at }],
    -- every ACTIVE staff member: private.staff_day_windows(b, s, p_local_date); ordered by staff sort, staff id, starts_at
  blocks:  [{ appointment_id, staff_id, starts_at, ends_at, buffer_after_min }]
    -- v_manager → []; else status in ('booked','confirmed','completed','no_show'),
    -- staff_id is distinct from my_staff_id(b), starts_at < day_end, ends_at + buffer > day_start;
    -- ordered by staff_id, starts_at, id. EXACTLY these five keys: no client, price, status or source.
}
```

#### 2.6.3 `today_summary` (stable; `_impl(p_business_id, p_now default now())`)

`today = (p_now at time zone tz)::date`; the day is `[today 00:00, today+1 00:00)` local, as instants. "Of today" = `starts_at` inside the day. Scope: `v_manager` → every appointment of the business; else `staff_id = my_staff_id(b)` (null → nothing).

```
{ local_date, timezone, currency,
  scope: 'business' | 'own',
  counts: { total,      -- today, in scope, status <> 'cancelled'
            remaining,  -- today, in scope, booked/confirmed, ends_at > p_now
            to_mark },  -- in scope, booked/confirmed, ends_at <= p_now, ANY date (all of them, not capped)
  expected_revenue_cents,   -- key always present; v_manager: Σ over the WHOLE business, today, status in
                            -- (booked, confirmed, completed) of (completed ? coalesce(charged_cents, total_cents) : total_cents);
                            -- otherwise JSON null (decided here, never in the wrapper)
  next:    [≤ 5]  { appointment_id, staff_id, starts_at, ends_at, status, client_id, client_name, service_ids }
           -- today, in scope, booked/confirmed, ends_at > p_now (in progress included); by starts_at, id
  gaps:    [≤ 10] { staff_id, starts_at, ends_at, minutes }
  to_mark: [≤ 20] { appointment_id, staff_id, starts_at, ends_at, status, client_id, client_name, service_ids }
           -- the rows counted in counts.to_mark; by ends_at desc, id
}
```
`client_name` = `full_name`, or `null` for a walk-in without client or an erased client. `service_ids` = `appointment_services.service_id` by position. No prices per item.

**Gaps**, per active staff member s in scope: `min_len(s)` = the smallest `coalesce(custom_duration_min, duration_min)` over active services s offers (none → s has no gaps); `from` = the first instant ≥ `p_now` whose local minute-of-day is a multiple of `slot_step_min`; free = (union of `staff_day_windows(b, s, today)`) − (union of s's booked/confirmed `[starts_at, ends_at + buffer)`) ∩ `[from, day_end)`. Each maximal free interval with length ≥ `min_len(s)` is a gap (`minutes` = its whole minutes). Ordered by starts_at, staff sort, staff id. Same busy rule as availability (0004): completed/no-show/cancelled never block.

#### 2.6.4 `set_appointment_status` (volatile)

After 1–2 and the role check: `p_status ∉ ('confirmed','completed','no_show')` or `p_from_status` not an appointment status → `22023`. Then:
1. current = `p_status` → return `changed: false` (no write, no event, no planner).
2. current ≠ `p_from_status` → **AN021**.
3. Target `confirmed`: current must be `booked`, else **AN020**.
4. Target `completed`/`no_show`: `starts_at > now()` → **AN023**. From `booked/confirmed`: allowed. From `completed/no_show/cancelled` (correction): not `v_manager` and `now() > ends_at + correction_window_days` → **AN022**.
5. `update … set status = p_status, charged_cents = case when p_status = 'completed' then charged_cents end, cancelled_by = null, cancel_reason = null` (the trigger writes `status_changed`, actor `staff`) → notify `'false'` → planner `status_changed`.

Returns `{ appointment_id, status, from_status, changed }` (`from_status` = the status before the call).

#### 2.6.5 `cancel_appointment` (volatile)

After 1–2 and the role check: `p_reason ∉` the 6 `cancel_reason` codes, `p_notify` null or bad `p_from_status` → `22023`. Then:
1. current = `cancelled` → `changed: false` (reason unchanged, no write).
2. current ≠ `p_from_status` → **AN021**.
3. From `booked/confirmed`: allowed any time (no `cancel_min_notice_min`: that rule is the client's). From `completed/no_show` (correction): not `v_manager` and past the window → **AN022**.
4. `effective_notify = p_notify and current in ('booked','confirmed') and starts_at > now()`.
5. `update … set status = 'cancelled', cancelled_by = case p_reason when 'client_request' then 'client' else 'business' end, cancel_reason = p_reason, charged_cents = null` → revoke **every** live `booking_tokens` row of the appointment (`revoked_at = now()`) → notify = effective → planner `cancelled`.

Returns `{ appointment_id, status: 'cancelled', from_status, changed, cancelled_by, cancel_reason, notify, sms_queued }` (on `changed: false`: the stored `cancelled_by`/`cancel_reason`, `notify` and `sms_queued` false).

#### 2.6.6 `staff_move_appointment` (volatile)

1. Membership (`42501`); appointment of the business (`42501`); `p_idempotency_key`, `p_new_starts_at` or `p_notify` null → `22023`.
2. `pg_advisory_xact_lock(hashtextextended('staff_move:' || p_business_id || ':' || p_idempotency_key, 0))`.
3. `request_hash` = hex sha256 of the jsonb text of `{appointment_id, new_starts_at: extract(epoch from p_new_starts_at), new_staff_id, allow_outside_hours: coalesce(…, false), allow_buffer_overlap: coalesce(…, false), notify}`.
4. **Replay**: a `move_requests` row for `(p_business_id, p_idempotency_key)` → `created_by is distinct from auth.uid()` → `42501`; other hash → **AN004**; else return the stored `result` with `replayed: true`. Checked **before** the ownership rule: a retry must replay even after the move handed the appointment to a colleague.
5. Lock the appointment; role check (on the current `staff_id`) → `42501`; status not `booked/confirmed` → **AN020**.
6. `effective_notify = p_notify and p_new_starts_at > now()`; set the notify setting; remember queued ids.
7. `private.move_core(p_business_id, p_appointment_id, p_new_starts_at, p_new_staff_id, 'staff', p_allow_outside_hours, p_allow_buffer_overlap, now())` — AN001 (service overlap / exclusion), AN003, AN005/AN006 without flag, AN008 (inactive/foreign staff); writes `rescheduled`/`reassigned`, calls the planner `moved`; same time and staff = no-op.
8. Build the result, insert the `move_requests` row (also for a no-op), return.

Result: `{ appointment_id, staff_id, starts_at, ends_at, warnings, from_staff_id, from_starts_at, replayed, notify, sms_queued }` (`warnings` ⊆ `['outside_hours','buffer_overlap']`; `from_*` = values before the move). A failed attempt stores nothing, so the same key may run again.

**Key semantics (UI):** one key per *attempt* = one exact payload (appointment, time, staff, flags, notify). A retry after a network error/timeout resends the identical payload with the same key. Any change (another time, confirming a D8 flag after AN005/AN006, toggling notify) is a new attempt with a new key.

#### 2.6.7 `search_clients` (stable, definer)

1. Membership (`42501`). `p_query` null → no rows; `char_length(p_query) > 100` → `22023`.
2. `v_norm` = `private.normalize_greek(p_query)`, every character that is not a letter, digit or space replaced by a space, spaces collapsed, trimmed. `char_length(replace(v_norm, ' ', '')) < 2` → no rows.
3. Candidates: `clients` of the business with `erased_at is null and merged_into_id is null`.
4. **Phone mode** when `btrim(p_query) ~ '^[+0-9 ()./-]+$'`: `v_digits` = digits of the query; fewer than 3 → no rows; match `c.phone_e164 like '%' || v_digits || '%'`; rank 0 when it ends with `v_digits`, else 1.
5. **Name mode** otherwise: tokens = words of `v_norm` (at most 5). Each token t matches when `search_text like '%' || x || '%'` for x = t or one of the three words of `private.greeklish(t)` (so a Greek query finds a Latin-stored name; Latin tokens pass through unchanged). **All** tokens must match. Rank 0 when a word of `search_text` starts with the first token or one of its variants (`search_text ~ ('(^| )' || x)`), else 1.
6. **Fuzzy pass**, only when steps 4–5 found nothing and `char_length(v_norm) >= 4`: `extensions.word_similarity(x, search_text) >= 0.5` for x = `v_norm` or a variant of `private.greeklish(v_norm)`; ordered by the best similarity desc.
7. `last_visit_at` = latest `starts_at` of the client's `completed` appointments (any staff).
8. Order: rank (fuzzy: similarity desc), `last_visit_at desc nulls last`, `full_name`, `id`; `limit 20`.

### 2.7 Auto-complete and cron

`private.auto_complete_impl(p_now timestamptz default now()) returns integer` — SECURITY DEFINER, **no grants** (pg_cron runs it as postgres):
1. `set_config('anaklo.actor_type', 'system', true)`; `v_started := clock_timestamp()`.
2. Inner block: rows with `status in ('booked','confirmed')` and `ends_at + auto_complete_after_min minutes <= p_now` (per business), ordered by `ends_at`, `limit 1000`, `for update of a skip locked` → `status = 'completed'` (event `status_changed`, actor `system`, `actor_id` null) → notify `'false'` → planner `status_changed` per row. Never touches `cancelled`, `completed`, `no_show`.
3. Success → `record_job_run('auto_complete', v_started, true, n)`, return n (0 included: the heartbeat is written on every run). `exception when others` → the inner work is rolled back, `record_job_run('auto_complete', v_started, false, null, sqlstate)`, return `null`.

Cron: `create extension if not exists pg_cron with schema pg_catalog;` (objects live in schema `cron`; API roles get no USAGE on it) and `select cron.schedule('auto-complete', '*/10 * * * *', $$select private.auto_complete_impl()$$);` (upsert by name, so resets rebuild it).

### 3.5 Mutations

- **No optimistic success** (rule 14): no `onMutate` cache writes. While pending, the action button shows its pending label and the sheet stays open; E15 and the success state render only in `onSuccess`. QueryClient defaults stay (`networkMode: 'always'`, `retry: 0`: an offline mutation fails at once instead of pausing).
- Each mutation call uses `.abortSignal(AbortSignal.timeout(15_000))`.
- **Attempt key**: `useAttemptKey(fingerprint)` returns `crypto.randomUUID()` and keeps it while the stable JSON fingerprint of the payload (without the key) is unchanged. Used by move and book.
- **Unknown outcome** (`offline` failure): the sheet shows «Δεν αποθηκεύτηκε — χωρίς σύνδεση» with «Δοκίμασε ξανά», which calls `mutate` with the **identical** variables (same key; for status/cancel the same payload, idempotent by §0.1). Inputs stay disabled; «Κλείσιμο» closes the sheet and invalidates the day, so the list shows whether it was saved.
- On success, and on AN001/AN020/AN021: `invalidateAppointmentChange` → `invalidateQueries` on `proKeys.day(b, d)` for the local date(s) of the old and new start, `['pro', b, 'today']` and `['pro', b, 'slots']`. AN005/AN006 → a confirm step («Εκτός ωραρίου…» / «Στρίμωγμα…»), then a new attempt with the flag. `warnings` of a success → a warning line in the success state. `notify && !smsQueued` → a neutral note «Δεν στάλθηκε SMS στον πελάτη» (always the case until 1.5).
- The «ενημέρωση με SMS» toggle appears for cancel and move only when the appointment has a client with a phone and starts in the future; default on.
