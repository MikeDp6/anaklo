## 0. Decisions in one place

1. **Tables.** The six new tables live in `public` with RLS on, **no policies, no grants** to `anon`/`authenticated`/`service_role`/`PUBLIC` (reachable only through definer RPCs). `platform_settings` and `vertical_defaults` live in `private` (same: RLS on, no grants).
2. **No plaintext secrets or phones in the verification tables.** OTP codes: HMAC-SHA256 with Vault `otp_hmac_key`, bound to the challenge id. Phones in `otp_challenges`, `trusted_devices`, `rate_limits`, `suppression_list`: `private.phone_hmac()` (Vault `phone_hmac_key`). Tokens and grants: `sha256` (high entropy, no key). `messages_log.to_e164` is the only plaintext phone (needed to send; wiped by `erase_client` in 1.8).
3. **All tokens are generated and hashed in SQL** (one implementation, rule 13). SQL returns a raw token exactly once to the Edge Function; the functions never hash or generate tokens.
4. **`otp_verify` never raises for code outcomes.** It returns `invalid | expired | locked | verified` and commits, so a wrong guess is always counted (a raised error would roll back the attempt counter). The function maps them to AN010–AN012.
5. **Test numbers only in the Edge Function.** SQL knows nothing about them: `otp_start` takes an optional `p_code`; the function passes `OTP_TEST_CODE` for a number in `OTP_TEST_NUMBERS`, only when `ANAKLO_ENV ≠ prod`. Otherwise SQL draws a random code.
6. **`start` also handles the trusted device.** With a valid `x-anaklo-td` for (business, phone) it answers `{ result: 'trusted', clients }` and sends nothing; otherwise it sends the OTP. `verify` returns the client list too. The `clients` action stays for refetches. Saves one round trip on both paths.
7. **No separate `trusted_device_check`/`trusted_device_issue` RPCs.** `clients_for_phone` is the check; `otp_verify` issues the device token in the same transaction. A `forget` action + `trusted_device_revoke` RPC lets the client revoke (ADR-0006 «ακυρώνεται από τον πελάτη»).
8. **Proof precedence** (clients and book): a live unconsumed grant → `otp`; else a valid trusted device → `trusted_device`; else **AN014**. A replay uses the original booking's `verified_via`, so the request hash matches.
9. **`book_appointment` requires an idempotency key** and takes a per-key advisory lock **before** the idempotency lookup, so two concurrent retries serialise and the second replays instead of failing on the consumed grant.
10. **The same notice rule for cancel and reschedule** (`change_until`, §2.7). Reschedule keeps the staff member and the booking's own length; a `slots` action (`manage_slots`) lists exactly the starts `move_core` will accept.
11. **Manage tokens are valid while** not revoked, `now() < expires_at` (created + 400 days) **and** `now() < appointment.ends_at + 30 days`. That window follows moves. No `last_used_at` anywhere: checks never write.
12. **Privacy notice version** is a code constant (`PRIVACY_NOTICE_VERSION` in `booking-schemas.ts`), passed by the Edge Function, never by the browser.
13. **Rate-limit windows are fixed UTC hours/days** (`date_trunc(…, p_now, 'UTC')`). They are caps, not user-visible rules, so no time zone is involved.
14. **Local seed relaxes the limits and the resend cooldown** (e2e re-runs from 127.0.0.1). pgTAP always sets `platform_settings` explicitly inside its transaction. The cooldown is therefore a setting (`otp_resend_seconds`, default 60).
15. **`public_slug_for_code` is on the proxy allow-list** as a fallback: the Worker/Vite resolve `/r/<code>` server-side; if Supabase does not answer, the page resolves it through `/api`.
16. **SMS failure fallback uses the catalogue phone.** The error body stays `{ error: { code, message } }`; the page already has `business.phone_e164` from `public_booking_catalogue`.
17. **Sends are awaited** in every action (the fake adapter is instant). `EdgeRuntime.waitUntil` for non-OTP sends is a 1.10 decision.
18. **`short_code`**: no UPDATE for `authenticated` (like `slug`); `service_role` keeps its table-level grants (provisioning never writes it). Generated by a BEFORE INSERT trigger (no function grant needed).
19. `spike-td` **stays** until the device tests of 1.10 (they moved there with the cookie test).

### 2.2 Crypto and Vault helpers (private, no grants)

Names are suggestions except where pgTAP calls them (`private.phone_hmac`).

| Helper | Behaviour |
|---|---|
| `private.vault_secret(p_name text) returns text` (plpgsql, stable) | `decrypted_secret` from `vault.decrypted_secrets` by name. Missing or shorter than 32 chars → `raise … using errcode = '55000'` (`vault secret <name> is missing`). The function maps it to 500 `internal`. |
| `private.phone_hmac(p_e164 text) returns text` (stable) | `encode(extensions.hmac(convert_to(p_e164,'UTF8'), convert_to(vault_secret('phone_hmac_key'),'UTF8'), 'sha256'), 'hex')`. **The key must never rotate** (suppression and bindings would be lost). |
| `private.ip_hmac(p_ip text) returns text` | same key, data `'ip:' \|\| p_ip`. |
| `private.otp_code_hmac(p_challenge_id uuid, p_code text) returns text` | key `otp_hmac_key`, data `p_challenge_id::text \|\| ':' \|\| p_code`. |
| `private.token_hash(p_token text) returns text` (immutable) | `encode(sha256(convert_to(p_token,'UTF8')),'hex')`. |
| `private.new_token(p_bytes int) returns text` (volatile) | unpadded base64url of `extensions.gen_random_bytes(p_bytes)`: `rtrim(translate(encode(…,'base64'),'+/','-_'),'=')`. 32 → 43 chars, 16 → 22 chars. |

### 2.3 `businesses.short_code`

- Column `short_code text not null`, `constraint businesses_short_code_format check (short_code ~ '^[a-z0-9]{6}$')`, `constraint businesses_short_code_key unique (short_code)`.
- `private.new_short_code()` (volatile): 6 chars from `a-z0-9` via `gen_random_bytes`, retried until unused (max 10 tries, then `raise`).
- Trigger `businesses_short_code` BEFORE INSERT, `private.set_business_short_code()` (SECURITY DEFINER): `new.short_code := coalesce(new.short_code, private.new_short_code())`.
- Existing rows (a remote DB may have them): add nullable → backfill with `new_short_code()` → `set not null`.
- **No** `grant update (short_code)` to `authenticated`; the `01_security` column list of `businesses` stays as it is.

### 2.6 RPCs

Pattern (ADR-0005): `private.<name>_impl` = SECURITY DEFINER, `set search_path = ''`, all checks inside; `public.<name>` = `language sql`, SECURITY INVOKER, same parameters **without `p_now`**, calls the impl (which then uses `now()` by default). `_impl` signatures below = wrapper parameters + `p_now timestamptz default now()` last. Volatility: the wrapper matches the impl. Grants: `EXECUTE` on **both** impl and wrapper, only to the roles listed.

| RPC (wrapper params) | Returns | Vol. | Roles |
|---|---|---|---|
| `otp_start(p_business_id uuid, p_phone text, p_locale text, p_service_ids uuid[], p_staff_id uuid, p_starts_at timestamptz, p_ip text, p_code text default null)` | jsonb `{challenge_id, message_id, code, expires_at, resend_at}` | volatile | service_role |
| `otp_verify(p_business_id uuid, p_phone text, p_challenge_id uuid, p_code text)` | jsonb `{result:'verified', grant, grant_expires_at, trusted_device_token}` \| `{result:'invalid', attempts_left}` \| `{result:'expired'}` \| `{result:'locked'}` | volatile | service_role |
| `clients_for_phone(p_business_id uuid, p_phone text, p_grant text, p_trusted_device_token text)` | jsonb `{verified_via, clients:[{id, first_name}]}` | **stable** | service_role |
| `book_appointment(p_business_id uuid, p_idempotency_key uuid, p_service_ids uuid[], p_staff_id uuid, p_starts_at timestamptz, p_phone text, p_client_id uuid, p_new_client jsonb, p_grant text, p_trusted_device_token text, p_marketing_box text, p_policy_version text)` | jsonb `{appointment_id, staff_id, starts_at, ends_at, total_cents, replayed, verified_via, manage_token, message_ids, next_visit_hint}` | volatile | service_role |

`message_ids` everywhere = `array(select id from messages_log where business_id = … and appointment_id = … and channel = 'sms' and status = 'queued' order by created_at)`: the function sends them right after the RPC committed. Returning them on a replay too heals a confirmation whose first send never ran.

Common rules: every public-booking impl except `trusted_device_revoke` starts with «business exists and `booking_enabled`» else **AN009**. Invalid arguments that the schemas already exclude (null key, unknown `p_locale`/`p_marketing_box`/`p_outcome`, malformed `p_code`) → `22023`. `otp_start` and `otp_verify` **never read `public.clients`** (identical behaviour for every number).

#### 2.6.1 `otp_start` — checks in this order, nothing written before step 9

1. AN009. 2. `22023` for bad `p_locale` / `p_code` (must be null or `^[0-9]{6}$`) / nulls. 3. **AN018** unless `p_phone ~ '^\+3069[0-9]{8}$'`.
4. **Slot still free**: a row of `private.available_slots_impl(p_business_id, p_service_ids, p_staff_id, d, d, 'public', null, p_now)` with `starts_at = p_starts_at`, `d` = local date of `p_starts_at` in the business zone; else **AN001** (AN003/AN008 propagate). No SMS for a taken or invalid slot.
5. `sms_enabled = false` → **AN017**.
6. A challenge for (business, `phone_hmac`) with `created_at > p_now - otp_resend_seconds` → **AN019**. `otp_resend_seconds = 0` skips the check (as built: a start that waited on the per-phone lock would otherwise see the challenge committed meanwhile as newer than its own `p_now`).
7. Current-window counts: `otp_phone_hour` (key `phone_hmac(p_phone)`) ≥ `otp_per_phone_hour`, or `otp_ip_hour` (key `ip_hmac(coalesce(p_ip,'unknown'))`) ≥ `otp_per_ip_hour` → **AN013**.
8. `otp_business_day` (key `p_business_id::text`) ≥ `otp_per_business_day`, or `sms_platform_day` (key `'platform'`) ≥ `sms_daily_cap` → **AN017**.
9. Upsert +1 on `otp_phone_hour`, `otp_ip_hour`, `otp_business_day` (not `sms_platform_day`: the claim counts real sends). Windows: `date_trunc('hour'|'day', p_now, 'UTC')`.
10. Insert the challenge (`code = coalesce(p_code, new_otp_code())`, `expires_at = p_now + 5 min`) and the message (`channel 'sms'`, `template/category 'otp'`, `to_e164 = p_phone`, `locale = p_locale`, `client_id null`, `otp_challenge_id`, `dedupe_key 'otp:<challenge_id>'`, `scheduled_for = p_now`).
11. Return `{challenge_id, message_id, code, expires_at, resend_at = created_at + otp_resend_seconds}`. The code leaves SQL only here, only to `service_role`; it is stored nowhere in plaintext.

A resend is a new `start` (new challenge, new code). Older challenges are not invalidated; the page always verifies the latest `challenge_id`.

#### 2.6.2 `otp_verify` (never raises for the code outcome; commits every counted attempt)

AN009 first (raising here is fine: nothing was counted). Then `select … for update` the challenge by `id = p_challenge_id and business_id = p_business_id and phone_hmac = phone_hmac(p_phone)`:
- not found, `verified_at` set, or `expires_at <= p_now` → `{result:'expired'}` (also a challenge of business A tried in B, or another phone);
- `attempts >= 5` → `{result:'locked'}`;
- code malformed or `otp_code_hmac(id, p_code) <> code_hmac` → `attempts + 1`; if now 5 → `{result:'locked'}`, else `{result:'invalid', attempts_left: 5 - attempts}`;
- match → `verified_at = p_now`, grant = `new_token(32)` (`grant_hash`, `grant_expires_at = p_now + 10 min`), and a trusted device (`new_token(32)`, `expires_at = p_now + 180 days`) for (business, `phone_hmac`) → `{result:'verified', grant, grant_expires_at, trusted_device_token}`.

`phone_verified_at` is **not** written here (only by `book_appointment`, OTP path).

#### 2.6.3 Verification check (`clients_for_phone`, `book_appointment`)

A grant is **live** for (business, phone) when a challenge has that `business_id`, `phone_hmac = phone_hmac(p_phone)`, `grant_hash = token_hash(p_grant)`, `grant_used_at is null`, `grant_expires_at > p_now`. A trusted device is **valid** when a row has that `business_id`, `phone_hmac`, `token_hash = token_hash(p_token)`, `revoked_at is null`, `expires_at > p_now`. Precedence: live grant → `otp`; else valid device → `trusted_device`; else **AN014**. A grant bound to another business, phone or already used is simply not live.

`clients_for_phone` (stable, **does not consume** the grant): AN009 → check → clients with `business_id`, `phone_e164 = p_phone`, `erased_at is null`, `merged_into_id is null`, ordered by `created_at, id`, limit 20, each `{id, first_name: split_part(btrim(full_name), ' ', 1)}`.

#### 2.6.4 `book_appointment`

0. `22023` if `p_idempotency_key` is null, `p_marketing_box` not in `('not_shown','unchecked','checked')`, or the box is shown and `p_policy_version` is not 1–40 chars. Then `pg_advisory_xact_lock(hashtextextended('book_appointment:' || p_business_id || ':' || p_idempotency_key, 0))`.
1. **Idempotency first.** If an appointment `(business_id, idempotency_key)` exists (**replay**):
   - proof = the grant consumed by exactly this appointment (`grant_hash = token_hash(p_grant)`, `grant_appointment_id = existing.id`, `p_now < grant_expires_at`, same business and `phone_hmac`), or else the §2.6.3 check (raises AN014); the check never consumes;
   - `book_core(…)` with the same arguments as step 3 but `p_verified_via = existing.verified_via` → returns `replayed: true`, or **AN004** when the payload differs;
   - a **new** manage token (`issued_for 'booking'`); no grant consumption, no `phone_verified_at`, no consent, no planner. Return (step 6).
2. **Proof.** If `p_grant` is given: `update otp_challenges set grant_used_at = p_now where` it is live `returning id` → `verified_via 'otp'`. Else (or 0 rows) a valid trusted device → `'trusted_device'`. Else **AN014**.
3. `private.book_core(p_business_id, 'public', p_service_ids, p_staff_id, p_starts_at, p_client_id, p_new_client, 'online', v_verified_via, p_phone, p_idempotency_key, false, false, null, p_now)` (actor `client`, recheck, `AN001/3/7/8/9`, planner `'created'`). `p_new_client` = `{full_name, locale}` only. If it raises, the whole transaction (grant consumption included) rolls back, so the same grant can try another slot.
4. OTP path only: `otp_challenges.grant_appointment_id = <appointment>`; `update clients set phone_e164 = p_phone, phone_verified_at = p_now` for the appointment's client (one UPDATE, so `reset_phone_verification` keeps it). The trusted-device path never writes `phone_verified_at`.
5. Consent (box shown only): `v_granted = (p_marketing_box = 'unchecked')`. The client's latest (`created_at desc, id desc`) non-withdrawn `marketing_sms` record: if it exists with `granted = v_granted` → nothing; else insert `(purpose 'marketing_sms', legal_basis 'soft_opt_in', granted v_granted, source 'booking_form', policy_version p_policy_version, given_by 'client', created_by null)`. A checked box is recorded as a refusal (`granted false`). Marketing eligibility (completed visit, Phase 2) is not decided here.
6. Return `{appointment_id, staff_id, starts_at, ends_at, total_cents, replayed, verified_via, manage_token, message_ids, next_visit_hint: private.next_visit_hint_impl(p_business_id, p_now)}`.

#### 2.6.5 Manage tokens and `change_until`

- Issue: `new_token(16)` (22 chars), store `token_hash`, `expires_at = p_now + 400 days`.
- Resolve (every `manage_*`): `token_hash = token_hash(p_token)`, `revoked_at is null`, `p_now < expires_at`, and the appointment has `p_now < ends_at + 30 days`; else **AN015**. Resolving never writes.

#### 2.6.9 `claim_messages` and `record_send_result`

`claim_messages(p_ids)`: nothing when `sms_enabled = false`. Otherwise `for update skip locked` the rows with `id = any(p_ids)`, `status 'queued'`, `channel 'sms'`, `scheduled_for <= p_now`, oldest first, **at most `sms_daily_cap − sms_platform_day`** (the counter row is locked and incremented by the number claimed; never more than the cap per UTC day, also with concurrent claimers). Rows with `to_e164 is null` → `cancelled`, `error 'no_recipient'`, not returned. Rows other than OTP (clients can trigger them again and again through a manage link or a trusted device):
- stop `sms_otp_reserve_pct` % of the cap earlier and **stay queued** (the rest of the day is for OTP);
- count on `sms_phone_day` (key `phone_hmac(to_e164)`, every business) and `sms_business_day` (key business uuid); over `sms_per_phone_day` / `sms_per_business_day` → `cancelled`, `error 'rate_limited'`, and the refused hit is taken back;
- `booking_confirmed`, `reminder`, `rescheduled_by_client`: the appointment is read `for share skip locked`. Locked (a cancel or move in flight) → the row stays queued for that change's planner; not booked/confirmed → `cancelled`, `error 'superseded'`, no token. Each claimed row: `status 'sending'`, `attempts + 1`, `lease_id = gen_random_uuid()`, `lease_until = p_now + 60 s`. For `booking_confirmed`, `reminder`, `rescheduled_by_client` a **new** booking token (`issued_for 'message'`) is created and its id stored in `booking_token_id`. Returns:

```
[{ id, lease_id, to_e164, locale, template, category,
   business_name, short_code, timezone,
   starts_at (null for otp), staff_name (null for otp),
   manage_token (raw, only for the three templates above; else null) }]
```
Only `queued` rows are ever claimed: a row stuck in `sending` is never re-sent (1.5a's sweep marks it `unknown`). **The 1.5a sweep must never claim `otp` rows** (their code exists only in the `otp_start` response).

`record_send_result`: only when the row is `sending` with `lease_id = p_lease_id` (else returns false). `p_outcome`: `sent` → `status 'sent'`, `sent_at`, provider, id, segments, cost; `failed` → `failed` + `error`; `rejected` → `cancelled` + `error` (e.g. `recipient_not_allowed`). Clears the lease, sets `updated_at`. No automatic retry in 1.3.

## 3. HTTP: common rules (`public-booking`, `manage`)

- Reached only through the proxy: `POST /api/functions/v1/public-booking` and `POST /api/functions/v1/manage` → upstream `/functions/v1/<name>`. `verify_jwt = false`. Nothing changes on GET.
- `index.ts` order: `requireProxy(req, PROXY_SECRET)` (403/500) → `requireMethod(req, 'POST')` (405, `Allow: POST`) → config (`booking-config.ts`, §7; invalid → **500 `not_configured`** on every request) → `parseJsonBody(req, PublicBookingRequest | ManageRequest)` (400 `invalid_body`, 413) → for `public-booking` only: header `x-anaklo-business` must be a UUID equal (case-insensitive) to `body.business_id`, else **400 `business_mismatch`** → action.
- Database: one `createClient(SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, { auth: { persistSession: false, autoRefreshToken: false, detectSessionInUrl: false } })`; **only `.rpc()`**, never `.from()`.
- Trusted-device token: `x-anaklo-td` (forwarded by the proxy from the cookie of `x-anaklo-business` only), used only when `isBase64UrlOfLength(value, 32)`; else treated as absent. Client IP: `requireProxy(...).clientIp` (null → SQL uses `'unknown'`).
- Success: 200 with the schema's body, via `json()` (`no-store`, `nosniff`). Errors: `errorResponse(code, message, status)` → `{ error: { code, message } }`. Domain errors (`domainErrorCode(error)`) use the status of §2.1; any other database or runtime error → **500 `internal`**.
- Non-domain codes: `invalid_body` 400, `business_mismatch` 400, `forbidden` 403, `method_not_allowed` 405, `payload_too_large` 413, `proxy_not_configured` 500, `not_configured` 500, `internal` 500 (plus the proxy's own `not_found`, `upstream_*`).
- Logs: action, outcome code, SQLSTATE, message ids. **Never** phone numbers, codes, grants, tokens, names or bodies.
- Response header `x-anaklo-set-td`: a token → the proxy sets the cookie; `''` → the proxy deletes it (`Max-Age=0`). The proxy strips the header.
- **Identical responses for known and unknown numbers**: `start` never looks at clients on the OTP path; an unlisted recipient (§6) still gets `otp_sent`; timing does not depend on client existence.

## 6. Sending SMS (`_shared/send.ts`, `_shared/sms-provider.ts`)

`sendMessages({ rpc, provider, config, ids, extraVars })` (pure; the db client and adapter come from `index.ts`):
1. `claim_messages(ids)`.
2. Per row: if `config.allowedRecipients` is non-empty and does not contain `to_e164` → `record_send_result(…, 'rejected', …, 'recipient_not_allowed')`, outcome `rejected`.
3. Variables: `business` = `business_name`; `date`, `time` = `starts_at` in `timezone`, client `locale`, via `dates.ts` (date ≤ 9 septets, e.g. weekday + `dd/MM`; time `HH:mm`); `staff` = `staff_name`; `link` = `${SITE_HOST}/m/${manage_token}` (manage templates) or `${SITE_HOST}/r/${short_code}` (`cancelled_by_*`); `code` from `extraVars[id]`; `domain` = `SITE_HOST` without the port.

## 7. Configuration (`_shared/booking-config.ts`, pure: `parseBookingConfig(raw) → { ok, config } | { ok: false, problems }`)

## 10. As built (integration, 2026-09-28)

Where the build differs from the text above; the code and the tests are the reference.

- **`currency`** is part of `manage_view.business` (§2.6.6) and of `public_booking_catalogue.business` (0004): prices are shown in `businesses.currency`, never in a default. `CurrencyCode` in `booking-schemas.ts`.
- **Resend cooldown 0** = no cooldown (§2.6.1 step 6, pgTAP `10_public_booking`).
- **Grant consumption** (§2.6.4 steps 2 and 4): the CHECK `(grant_appointment_id is null) = (grant_used_at is null)` forbids setting `grant_used_at` alone, so step 2 locks the live grant (`select … for update`) and step 4 sets `grant_used_at` and `grant_appointment_id` in one UPDATE. The same serialisation (race checked by hand: one appointment, the second call replays).
- **`short_code`** has a placeholder `default ''` (so the generated Insert type keeps it optional); the trigger treats `''` like null.
- **Rate limits**: counters are incremented, then compared (count after the increment > limit ⇔ count before ≥ limit); a refusal raises, so nothing stays written. A per-phone advisory lock makes the cooldown and the per-phone count exact under concurrency.
- **Test clock**: `created_at = p_now` on challenges, trusted devices, tokens and consents.
- **Next-visit intervals** are counted in local calendar days of the business zone.
- **Edge Functions**: the handlers live in `_shared/public-booking-handler.ts` and `_shared/manage-handler.ts` (with `booking-rpc.ts`, `booking-runtime.ts`), so Vitest covers them; `index.ts` only reads the environment and builds the clients.
- **1.5a** in this file is step **1.5** of the plan since 2026-09-28 (C7).
- **Lock order** (review of 2026-09-28): `manage_cancel`, `manage_reschedule` and `move_core` (0004) lock the appointment `for no key update`, never `for update`: none of them changes a key column, and the weaker lock lets the foreign-key check (`for key share`) of a new manage token (a claim, a replay of `book`) through. With `for update` a claim holding its message row and a cancel holding the appointment (or a replay holding the day lock and a move holding the appointment) deadlocked (40P01). Race tests: `tests/db/public-booking-race.test.ts` (psql sessions in the local container).
- **SMS other than OTP are capped too** (same review): `sms_per_phone_day`, `sms_per_business_day`, `sms_otp_reserve_pct` in `platform_settings`, buckets `sms_phone_day`/`sms_business_day` (§2.4, §2.5, §2.6.9). The local seed relaxes the two caps like the OTP ones.
